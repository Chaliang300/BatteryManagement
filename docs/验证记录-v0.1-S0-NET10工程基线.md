# 验证记录 — v0.1 S0 .NET 10 工程基线（PR-S0-01）

- 日期：2026-11-08
- 范围：把 .NET Framework 4.8 + `csc.exe` 的基线迁移为 .NET 10 SDK 式工程，重建 `build.ps1`/`pack.ps1`，
  建立 xunit 单测，并按 D16 记录自包含单文件包体与解包行为
- 分支：`feat/s0-net10-baseline`（从 `origin/main` `1f6b6d3` 建立）
- 机器：Windows 11 Build 26220，.NET SDK 10.0.403（`%USERPROFILE%\.dotnet10` 就地部署），
  运行时 `Microsoft.NETCore.App 10.0.14` / `Microsoft.WindowsDesktop.App 10.0.14`

## 1. 做了什么

### 1.1 工程文件

| 文件 | 内容 |
| --- | --- |
| `src/PowerDock.Core/PowerDock.Core.csproj` | SDK 式，`net10.0`，`AssemblyName=PowerDock.Core`，`ImplicitUsings=disable`、`Nullable=disable`（保持 .NET Framework 时期源码命名空间与写法不变） |
| `src/PowerDock.App/PowerDock.App.csproj` | SDK 式，`net10.0-windows`，`OutputType=WinExe`，`UseWPF=true`，`UseWindowsForms=true`（托盘 `NotifyIcon` 与 `System.Drawing` 图标绘制），`AssemblyName=PowerDock`，`ApplicationManifest=..\..\app.manifest`，`RootNamespace=PowerDock.App`，`StartupObject=PowerDock.App.Program` |
| `tests/PowerDock.Core.Tests/PowerDock.Core.Tests.csproj` | `net10.0`，xunit 2.9.3 + `Microsoft.NET.Test.Sdk` 17.14.1 + `xunit.runner.visualstudio` 3.1.5，引用 Core |
| `PowerDock.sln` | 聚合上述三个工程，`dotnet build` 一条命令覆盖源码与测试编译 |

未提交 `global.json`：不锁 SDK 补丁版本（团队升级 SDK 时不会连锁失败）。

### 1.2 为编译通过做的最小修复（不删功能、不禁用自检项）

| 位置 | 原实现 | 现实现 | 理由 |
| --- | --- | --- | --- |
| `Core/Storage/SettingsStore.cs` 4 处 | `System.Web.Script.Serialization.JavaScriptSerializer` | 新增 `Core/Storage/SettingsJson.cs`，改用 `System.Text.Json` | .NET 10 无 `System.Web.Extensions` |
| `App/Shell/SingleInstanceService.cs` | `new NamedPipeServerStream(..., PipeSecurity)` 8 参构造 | `NamedPipeServerStreamAcl.Create(..., PipeSecurity)` | .NET Core+ 删除了带 ACL 的构造函数，ACL 语义保留（仍限制为当前用户） |
| `Core/Storage/AtomicFile.cs` | 默认 `Encoding.UTF8` | 显式 `new UTF8Encoding(false)` | `File.WriteAllText` + `Encoding.UTF8` 会写 3 字节 BOM；统一为无 BOM UTF-8，读取侧仍兼容带 BOM 旧文件 |

`settings.json` 兼容性：字段名仍为 PascalCase、输出仍为紧凑单行、反序列化大小写不敏感（`PropertyNameCaseInsensitive`）、
中文别名不转义为 `\uXXXX`（`UnsafeRelaxedJsonEscaping`）。旧的 .NET Framework 时期文件与手改小写字段名的文件都做了用例。

未沿用的基线文件：`PowerDock.exe.config`（`.NETFramework,Version=v4.8` + `Switch.System.Windows.DoNotScaleForDpiChanges`，
.NET 10 用 `runtimeconfig.json`，且 .NET Core+ WPF 默认即为 Per-Monitor DPI）。

### 1.3 脚本

- `build.ps1`：`dotnet build PowerDock.sln`，支持 `-Configuration`、`-OutputDirectory`、`-NoRestore`，
  打印错误/警告计数与产物绝对路径，失败返回真实退出码。构建范围是解决方案级（Core + App + Tests），
  所以测试工程编译失败也会让构建失败，不会出现「源码能编、测试编不过」的假绿。
- `pack.ps1`：`dotnet publish -c Release -r win-x64 --self-contained true -p:PublishTrimmed=false -p:PublishSingleFile=true
  -p:IncludeNativeLibrariesForSelfExtract=true`，产出 `dist\PowerDock-v<Version>-win-x64\` 与同名 zip，
  打印**发布耗时、单文件 exe 字节、解包后总字节与文件数、zip 字节、压缩比、exe/zip SHA256**，
  并把同样的度量写入 `dist\pack-report-<Version>-<Rid>.json`。
- `tools/dotnet-sdk.ps1`：SDK 探测（`PATH` → `DOTNET_ROOT` → `%ProgramFiles%\dotnet` → `%LOCALAPPDATA%\Microsoft\dotnet`
  → `%USERPROFILE%\.dotnet10` / `.dotnet`），不硬编码用户名；全部失败时打印中文安装指引并非零退出。


结论：**未裁剪自包含单文件成立**——发布目录里没有并排的 DLL，WPF 原生库被收进 exe。

可接受上限仍待确认（见第 3 节）。降低体积的可用杠杆 `EnableCompressionInSingleFile=true` 本轮未开启，保持基线原样。

### 2.4 单文件解包行为（D16 要求的事实）

首次运行前后对比 `%TEMP%\.net`：

```
运行前：%TEMP%\.net 不存在
运行后：%TEMP%\.net\PowerDock\RIxR2pUcpgfL\  共 5 个文件 / 8,215,952 字节
        D3DCompiler_47_cor3.dll        4,741,488
        wpfgfx_cor3.dll                1,956,648
        PresentationNative_cor3.dll    1,235,240
        PenImc_cor3.dll                  158,032
        vcruntime140_cor3.dll            124,544
```

启动耗时（`--help` 立即退出，测「进程启动 + 解包」这一段）：

| 轮次 | 耗时 | 说明 |
| --- | --- | --- |
| 冷启动（先删 `%TEMP%\.net\PowerDock`） | 109 ms | 含 8.2 MB 原生库解包 |
| 预热后 2–4 轮 | 57 / 68 / 58 ms | 复用已解包目录 |

因此单文件分发对启动的影响是**首轮约 +50 ms 的一次性解包**，不是每次启动都解包；
`%TEMP%` 不可写的受限环境需要单独验证（见第 3 节）。

## 3. 哪些没验

1. **「无 SDK 的目标机可启动」只验了一半**：本机 PATH 上的 `dotnet` 确实没有 SDK，脚本靠探测绕过了它；
   但机器里装着 SDK，未在「完全没有 SDK」的干净机器上跑过 `build.ps1`（脚本侧的中文失败路径是构造性验证的）。
2. **托盘与窗口只验了自检内部结论，没有人眼可视确认**：TRAY-01/02、WIN-01 由自检内部渲染与句柄检查判定为通过，
   但任务栏溢出区、浅色任务栏反色、真实首帧、Acrylic 材质均未截图取证。工作区 exe 降权（`Shell_NotifyIcon` Win32=5）
   的既有陷阱本轮未复现，也未在工作区外路径重测。
3. **并发二启与置前拒绝未复验**：属 S0 退出条件，需要多进程与真实前台交互，本 PR 未覆盖。
4. **DPI / 多显示器 / 窗口位置校正未验**：旧的 `AppContextSwitchOverrides`（`DoNotScaleForDpiChanges=false`）未延续，
   .NET Core+ WPF 默认 Per-Monitor DPI，行为差异需实际拖动窗口与切换缩放比例确认。
5. **包体上限未决**：165 MB exe / 66 MB zip 只是实测值，D16 的「可接受上限」仍需产品侧确认；
   若上限更严，可选项是 `EnableCompressionInSingleFile`（体积降、启动解压增）或重新评审运行时。
6. **受限 TEMP 环境未验**：单文件解包依赖 `%TEMP%` 可写；企业策略禁用 TEMP 执行的情形未测。
7. **跨 Windows 版本未验**：仅在本机 Windows 11 Build 26220 验证；Windows 10 与低于 22621 的 Build 下
   Acrylic/圆角降级行为未测。
8. **`dotnet test` 只在本机 SDK 下跑过**；UI 生命周期相关代码（托盘、窗口、单实例）没有自动化测试覆盖，
   它们只有 `--self-test` 这一条路径。
