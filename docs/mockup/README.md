# PowerDock 界面设计还原 · HTML 版

把 Ardot 设计稿（file 744804852905562，共 7 块画板）还原成一份可直接在浏览器打开的静态页面。
没有构建步骤、没有依赖、不联网也能跑。

---

## 一、怎么打开

直接双击 `index.html`，或把它拖进浏览器。

如果希望用 `http://` 打开（某些浏览器对 `file://` 下的 `backdrop-filter` 有额外限制）：

```powershell
# 在本目录下执行
python -m http.server 5173
# 然后访问 http://localhost:5173/
```

推荐 Chrome / Edge 111 以上。低于这个版本，`color-mix()` 与 `mask-composite` 会失效，玻璃的边缘高光会丢失（不至于错版，但质感会掉一档）。

## 四、样式体系

### 4.1 主题变量

变量定义在 `[data-theme="dark"]` / `[data-theme="light"]` 上，**不是 `:root`**。

这么写是为了支持局部换肤：页面里用了 `.theme-scope[data-theme="…"]` 包裹区块，
同一个页面内可以并排显示深色和浅色，各自独立。切换顶栏的主题按钮只改 `<html>` 上的值，
不会影响这些固定了主题的对照区块——这是刻意的，否则深浅对照就没法看了。

主要变量：

| 变量 | 作用 | 深色 | 浅色 |
|---|---|---|---|
| `--glass-top` / `--glass-mid` / `--glass-bot` | 玻璃渐变的三段 | 白 26% / 4% / 17% | 白 95% / 13% / 46% |
| `--edge-a` / `--edge-m` / `--edge-b` | 描边渐变 | 白 72% / 16% / 48% | 白 96% / 28% / 62% |
| `--t1` … `--t4` | 四级文字 | 白 92% → 18% | 墨 92% → 18% |
| `--track` / `--fill` | 电量槽与填充 | 白 12% / 45% | 墨 10% / 40% |
| `--accent` | 品牌色（仅交互与选中） | `#6BA6FF` | `#2F6FE0` |
| `--ok` / `--off` | 在线·充电 / 离线 | `#34D399` / `#8A8F99` | `#12A870` / `#7C838F` |
| `--warn` | 电量偏低 20–40% | `#FF9F0A` | `#C25E00` |
| `--danger` | 电量告急 &lt;20% | `#FF6B6B` | `#C0342B` |
| `--hair` | 极细分割线 | 白 8% | 墨 10% |

品牌色和状态色在浅色下**必须降明度**，直接沿用深色值会在浅底上发飘——这条写在了设计稿里，这里照着做了。

### 4.2 玻璃材质的三层构成

`.widget` 的质感不是 `backdrop-filter` 一项就能出来的，它由三层叠加：

1. **背景渐变**：`linear-gradient(180deg, 顶部亮 → 中段透 → 底部回光)`，模拟光线从上方穿过玻璃；
2. **1px 渐变描边**：用伪元素 + `mask` 挖出一个 1px 的环（`mask-composite: exclude`），
   上亮下暗。这是"边缘折射"的关键，去掉它立刻变成普通毛玻璃；
3. **内阴影**：顶部 1px 白色高光 + 底部 2px 反光，再叠一层外投影做悬浮。

```css
.widget {
  background: linear-gradient(180deg, var(--glass-top) 0%, … , var(--glass-bot) 100%);
  backdrop-filter: blur(48px) saturate(180%);
  box-shadow: inset 0 1px 0 var(--inner-1), inset 0 -2px 6px var(--inner-2), var(--widget-shadow);
}
.widget::before { /* 1px 渐变描边 */ }
```

**注意一个副作用**：`backdrop-filter` 采样的是元素背后真实的像素。所以组件外面必须有"底色"可采样，
这就是 `.theme-scope` 存在的第二个理由（第一个理由是并排换肤）——它给每块玻璃铺了一张浅色或深色的站台。
单独把 `.widget` 拷到别的页面，它会采样到那个页面的背景，颜色会变。

### 4.3 组件尺寸

尺寸是设计稿的绝对值，不随视口缩放（移动端整体 `zoom`，见第七节）。

| | 尺寸 | 圆角 | 内边距 | 显示台数 | 行结构 |
|---|---|---|---|---|---|
| 小 2×2 | 173×173 | 22 | 14 | 3 | 名称行 + 满宽条（唯一的重排） |
| 中 4×2 | 362×173 | 27 | 16 | 5 | 单行四列 |
| 大 4×4 | 362×362 | 27 | 22 | 7 | 单行四列 + 汇总页脚 |

设备行用 grid 对齐，列宽写死，保证"名称 / 条 / 百分比"各自成列：

```css
/* 中号 */
.dev { grid-template-columns: 5px 13px 84px 1fr 34px; gap: 10px; }
/* 大号 */
.wlist--lg .dev { grid-template-columns: 6px 14px 86px 1fr 40px; }
/* 小号：条独占第二行 */
.wlist--sm .dev { grid-template-columns: 4px 1fr; }
```

条的长度只由 `--pct` 决定，所有行共用同一起点与同一最大长度——这是"每台等权重"能成立的技术前提。

### 4.4 状态与颜色

状态通过 `data-state` 属性驱动，不写在类名里：

```html
<li class="dev" data-state="offline">…</li>
```

```css
.dev[data-state="offline"] { opacity: .5; }
.dev[data-state="offline"] .dev__dot { background: var(--off); }
```

三态约定：

- 在线 —— 实心绿点，正常渲染；
- 离线 —— 灰点 + 整行 50% + 电量位显示「—」，**行高与顺序不变**（重排会让人以为设备消失了）；
- 未知 —— 1.4px 空心环。它表示"数据源不可用"，不是"设备离线"，两者混用会误导排查。

### 4.5 挂件不设表头

三档尺寸、深浅两版、桌面场景、主窗口里的挂件预览，都从**第一行设备**开始，顶部没有标题行。

理由是那一行只占地方、不产生信息：挂件显示什么，看设备名就知道；在不在线，看行首状态点就知道。
「电量 / 2/3 在线」等于把两件已经写在下面的东西又写了一遍，还吃掉了小号最紧张的 20px。

- **在线统计只在大号底部出现一次**：`共 8 台 · 6 在线 · 按电量升序 · 空闲 60s 刷新`。
  大号受 7 行上限截断，用户需要知道"还有一台没显示"，这条信息值得一行。
- **中号 / 小号不写任何统计**：行本身就是全部内容。
- **勾了但掉线的设备照常显示**，整行降到 50%、电量位写「—」，位置不动。
- 去掉表头后，列表的上边距一并归零（`.wlist` 原本 `margin-top: 12px` 是给表头让位的）。
- **2×2 的三行居中 + 固定 10px 间距**，不用 `space-between`：173 高只装三行，均分会把行距拉到 30px 以上，
  看起来像三个孤岛。10px 是三行抱团又不粘连的距离。
- 主窗口里的 2×2 预览同步了这条，并且**改成两行结构**（点 + 名称 + 百分比 / 电量条独占一行）——
  173 宽放不下四列，不改的话名称会被压成一个字。

## 六、交互说明

`app.js` 只做四件事，全部通过改 DOM 属性实现，CSS 负责表现：

1. **切换外观** —— 顶栏两个按钮改 `<html data-theme>`，并写入 `localStorage`；
   首次访问若无记录，跟随系统 `prefers-color-scheme`。
2. **切换壁纸** —— 循环 1/2/3 三套光斑配色，用来观察同一块玻璃在不同底色上的采样结果。
3. **主窗口联调**（只驱动带 `data-live` 的那一个窗口，另外两个是静态状态图）：
   - **Dock** —— 四个目的地（概览 / 设备管理 / 组件 / 设置）在同一窗口内换 `pane`，不重开窗口；
   - **勾选** —— 设备卡右上角的圆点、组件页清单改的是同一份 `onSet`：标题栏计数、概览第 4 格、
     卡片脚注（在组件中 / 未显示）、挂件行数一起跟着变；
   - **尺寸** —— 组件页右上角的 seg 切换后，挂件按 173×173 / 362×173 / 362×362 变，
     行数上限跟着 3 / 5 / 7。
4. **配置页勾选** —— 整行可点，切换 `aria-pressed` 与 `aria-selected`，实时更新"已选 N / 8"。

键盘可达性：设备行用 `role="option"` + `aria-selected`，放在 `role="listbox"` 里；
勾选是原生 `<button>`，自带焦点环（`:focus-visible`）。尊重 `prefers-reduced-motion`，
开启后所有过渡降到 0.01ms。

## 七、响应式

| 断点 | 处理 |
|---|---|
| > 1000px | 主窗口居中单列，配置页左面板右说明 |
| ≤ 1000px | 配置页改单列，状态区三列自动降为两列或一列 |
| ≤ 860px | 主窗口 `zoom: .86`，保持内部比例 |
| ≤ 700px | 顶栏换行，主窗口 `zoom: .70`，桌面场景改竖向排布 |
| ≤ 430px | 组件 `zoom: .88`，主窗口 `zoom: .58` |

**为什么用 `zoom` 而不是 `transform: scale()`**：`transform` 不改变元素占位，缩放后会在下方留出与视觉高度不符的空白，还会产生横向滚动条；`zoom` 会重新计算布局尺寸，滚动和锚点都正常。
代价是它不在标准轨道上（不过 Chrome / Safari / Firefox 126+ 都已支持）。

主窗口固定 880px，**不做流式自适应**——它的内部列宽（卡片四列、状态带四格、8 台柱状条）是按像素对齐的，
一旦允许拉伸，列就会错位。宁可整体缩放。

## 八、已知限制

这些是当前版本的边界，不是待修的 bug，特此说明：

1. **字体没有内嵌**。用的是 `Inter` / `Nunito` 的系统回退栈，未引入 Google Fonts（离线会失败）。
   如果本机没装这两个字体，大号数字会回退到 `Segoe UI`，rounded 的圆角感会丢失。
   要完全还原设计稿，需要把字体文件放进 `assets/` 并用 `@font-face` 引入。

2. **玻璃是"模拟"而非系统材质**。设计稿里说的 Liquid Glass 在 Windows 上并没有对应 API，
   这里是用多层渐变 + 描边 + 内阴影近似出来的。`backdrop-filter` 在关闭硬件加速、
   或浏览器不支持时，会退化成一块半透明纯色。

3. **组件必须放在有底色的容器里**。见 4.2，`backdrop-filter` 采样真实背景，
   脱离 `.theme-scope` 单独截图会出现颜色异常。

4. **深浅并排不跟随顶栏切换**。这是设计稿的要求（要能左右对照），
   不是 bug。要看另一种主题，改对应区块的 `data-theme` 属性。

5. **交互是演示性质**。勾选会联动计数、芯片与挂件预览，但不写 `settings.json`、不改真实配置；
   设备状态是写死的样例。真实实现里状态来自：
   蓝牙 `ConnectionStatus` + GATT 读失败计数、2.4G 接收器 HID 心跳、USB PnP 在场、本机 WMI。

6. **未覆盖的部分**：托盘右键菜单、设置页、设备详情浮层、`.ico` 多分辨率打包。
   这几块在设计稿里也没有，需要另行设计。

7. **颜色存在环境差异**。同一份 CSS 在不同显示器、不同色彩配置文件下会有可见色差，
   尤其是 `rgba(255,255,255,.04)` 这一级的极低透明度叠层。对比时请以同一台设备为准。

8. **移动端用 `zoom` 缩放，不是真正的流式布局**。手机上组件会整体缩小，
   字号随之变小，13px 的核心数字在 430px 屏上实际约 11.4px，接近可读下限。

## 十、主界面为什么是这套结构

前面出过三个结构完全不同的方案（`proposals/` 里留着 A · 底部 Dock、B · 侧栏 + 检查器、C · 组件工作台），
最后落在 A：**Dock 当唯一导航，横向空间全部留给内容**。理由是这一版要同时装下四件事——
看状态、管勾选、配组件、调设置——而 A 是三者里唯一能让 8 台设备一屏排开、且不给导航留一列宽度的结构。

### 概览的三层结构

| 层 | 内容 | 解决什么 |
| --- | --- | --- |
| 状态带 | 需充电 1（18% · MX Master 3S）/ 充电中 1 / 在线 7-8 / 在组件 5-8 | 四个数回答「要不要充电、几台在线、组件里几台」 |
| 焦点 | 左：最需要关注的一台（大数字 + 近 7 天趋势）；右：另外两台 + 其余 5 台汇总 | 一台要处理、两台要知道，8 台全覆盖 |
| 全貌 | 8 台排成一条柱状条，坏的那台用 --danger | 一台不漏，但不重复一遍设备页 |

配套的三条取舍：

- **整屏只有一处红**。状态带里只有「需充电」那格是红色描边+淡底，其余中性；
  下方柱状条里 18% 那根才再用一次红。红色一多，就没有「最需要关注」了。
- **不重复设备页**。上一版概览把 8 台做成 4×2 卡片，和设备页长得一模一样却少了勾选与别名，
  既不是概览也不是列表。现在换成柱状条：同样的 8 台，但只回答「谁低谁高」。
- **趋势只给最需要关注的那台**。7 天趋势有信息量，但四台都画就变成背景噪声；
  断连那天留 3px 短桩，不做插值。
