## 3. 产品边界

**做**

- 一个不需要装驱动、不联网、绿色运行的 Windows 电量中心。
- 聚合四类设备：蓝牙外设（键鼠/耳机）、2.4G HID 外设、系统电池（笔记本/UPS）、厂商私有协议设备。
- 三种呈现包括桌面常驻挂件、主窗口和三格电池组托盘图标。
- 低电量提醒、7 天电量趋势。

**不做**

- 不做设备参数写入（DPI、回报率等属于 VT9Status 这类专用工具）。
- 不改系统电源方案与 Windows 指针/滚轮设置。
- 不上传、不统计、不做账号体系。
- 不在首版做 Widgets Board 卡片（依赖 MSIX 打包身份，见 ADR-03）。

## 5. 架构总览

```
┌──────────────── 呈现层（多窗口，单 UI 线程）────────────────┐
│  WidgetWindow(3 档)   MainWindow   TrayIcon   Toast          │
└───────────────────────────▲─────────────────────────────────┘
                            │ INotifyPropertyChanged / 事件合并
┌───────────────── 应用层 DeviceStateService ─────────────────┐
│  去重合并 · 置信度裁决 · 刷新调度 · 历史写入 · 提醒判定        │
└───────────────────────────▲─────────────────────────────────┘
                            │ IDeviceProvider 统一契约
┌───────────────── 采集层（并发、无 UI 依赖）─────────────────┐
│ BluetoothProvider  HidProvider  WmiProvider  VendorProvider  │
└───────────────────────────▲─────────────────────────────────┘
                            │
┌───────────────── 基础设施 ─────────────────────────────────┐
│ SettingsStore(JSON 原子写)  HistoryStore(JSONL 日滚动)       │
│ SingleInstance(Mutex+Pipe)  Log(1MB 轮转)  SelfTest          │
└─────────────────────────────────────────────────────────────┘
```

**契约**：`IDeviceProvider` 提供发现、主动刷新、采集事件和异步释放。发现与失败也可上报，见 [协作契约 §5.3](../AGENTS.md#53-核心契约与数据模型)。

**线程模型**：Provider 后台执行采集，系统要求 UI 线程处理的授权由 App 协调；`DeviceStateService` 用 200ms 合并窗口收拢高频报告，只把最终状态推给 UI；UI 更新一律经 `Dispatcher.BeginInvoke`，禁止采集线程直接触碰控件（VT9 的 `configBusy` 竞态就是反例）。

## 6. 关键技术决策（ADR）

| # | 决策 | 结论 | 理由与代价 |
| --- | --- | --- | --- |
| 01 | 运行时 | **.NET 10 LTS + WPF**，S0 验证 win-x64 未裁剪自包含单文件（D16） | .NET 8 支持即将结束，SDK 禁用 WPF 裁剪。发布体积、首次解包、启动速度以 S0 实测为准 |
| 02 | UI 框架 | **WPF**，不采用 WinUI 3 | 设计稿原定 WinUI 3，但 WPF 已在 VT9 上验证过 DWM Acrylic、圆角、DPI、启动 639ms；WinUI 3 未打包时 Acrylic 与窗口行为受限，打包后又与“绿色免安装”冲突 |
| 03 | Widgets Board | **首版不做**，独立立项 | Widget Provider 需要 MSIX 打包身份与 Windows App SDK，一旦引入就放弃绿色免安装。先用桌面挂件覆盖同一使用场景 |
| 04 | 电量来源权威性 | **设备自报优先，系统视图兜底** | 同一设备被 BLE 与系统同时枚举时，按 `Vendor > Bluetooth(GATT) > Hid(0x06) > Wmi` 排序取值，其余作为交叉校验；差值 >5% 时在详情页标注“来源不一致”而不是静默丢一个 |
| 05 | 充电判定 | **只读查询，不猜** | 继承 VT9 结论：充电状态走独立只读电池查询，不看电量上涨趋势。查询失败时显示“上次充电中，等待更新”，45s 后降级为未知 |
| 06 | 存储 | **JSON 设置 + JSONL 历史，不引 SQLite** | 5 分钟粒度 7 天约 2000 条/设备，JSONL 日文件足够；卸载前关闭自启，退出后删除应用与数据 |
| 07 | 测试 | **xUnit 单测 + `--self-test` 内置自检双轨** | 单测覆盖解析/调度/持久化；自检覆盖需要真实设备与窗口的项，输出 `data/self-test.json`，沿用 VT9 的 105 项形式 |

## 7. 采集层设计

### 7.1 BluetoothProvider（BLE）

- `DeviceWatcher` 监听 `BluetoothLEDevice` 与 `DeviceInformation`（关联 AEP 容器），只保留已配对且有电池服务的设备。
- 服务 `0x180F` / 特征 `0x2A19`，先读取初值。若特征声明 `Notify`，订阅通知并检查订阅结果；仅支持读取或订阅失败时继续按 §8 轮询。[Bluetooth SIG Battery Service 1.1](https://www.bluetooth.com/wp-content/uploads/Files/Specification/HTML/BAS_v1.1/out/en/index-en.html)
- **GATT 会话必须缓存**：反复 `FromBluetoothAddressAsync` 会造成连接抖动与 30s 级延迟。会话失效（`ConnectionStatus=Disconnected`）才重建，重建带 1s/2s/4s 退避。
- 事件和读取统一更新各来源的成功采样时间。首次出数目标面向首发验证清单中的可达设备，连接超时、无电池服务或拒绝访问需有明确状态。
- 蓝牙关闭/适配器移除：监听 `Radio.StateChanged`，整层降级为“蓝牙已关闭”，不清空已缓存电量。

### 7.2 HidProvider（2.4G / 有线外设）

- 用 `SetupDiGetClassDevs` 枚举 HID 集合。在各集合的 Input / Feature 报告能力中查找 `UsagePage=0x06, Usage=0x20`（Battery Strength）。使用报告 ID、链接集合和逻辑范围解析，避免按顶层集合 Usage 排除鼠标、键盘。[HID 值能力](https://learn.microsoft.com/en-us/windows-hardware/drivers/hid/value-capability-arrays)
- 首选 `HidD_GetFeature` 读 Feature Report；设备不支持时退回解析输入报告中的 Battery Strength 字段。
- 厂商私有上报（如 VT9 的 `BA 01 01/02 xx`）走 `VendorProvider`，不混进通用 HID 解析。
- 每次读取以 `CreateFile`/`CloseHandle` 短连接完成，不常驻句柄，避免独占导致厂商驱动失效。

### 7.3 WmiProvider（系统电池）

- `Win32_Battery`（EstimatedChargeRemaining、BatteryStatus）为主，`GetSystemPowerStatus` 作为 1s 级快速兜底。
- `BatteryStatus` 6–9 表示充电。状态 2 只表明接入市电，充电结果待确认。系统汇总可读取 `GetSystemPowerStatus` 的 `BatteryFlag` 充电位，先处理未知和无系统电池标志，百分比 255 映射为未知。[Win32_Battery](https://learn.microsoft.com/en-us/windows/win32/cimwin32prov/win32-battery) · [SYSTEM_POWER_STATUS](https://learn.microsoft.com/en-us/windows/win32/api/winbase/ns-winbase-system_power_status)

### 7.4 VendorProvider（可插拔）

- 约定：`%LOCALAPPDATA%\PowerDock\providers\<name>\provider.json` 描述 VID/PID 与协议，DLL 只在用户显式启用时加载。
- 首版只做内置 VT9 一个用例，用来验证扩展点是否够用，不做第三方开放。

## 8. 刷新调度

| 场景 | 周期 | 触发 |
| --- | --- | --- |
| 设备上报事件 | 即时 | 特征通知 / 输入报告 |
| 充电中 | 15s 兜底 | 定时器 |
| 空闲（窗口可见） | 60s 兜底 | 定时器 |
| 仅托盘且空闲 | 5min | 主窗口和挂件均隐藏时降频 |
| 系统进入省电 / 锁屏 | 暂停主动轮询 | 电源状态通知 / 会话锁定通知 |
| 蓝牙适配器状态变化 | 立即全量重扫 | `Radio.StateChanged` |

**调度与时效**：按协作契约 §5.6 和 §6.7 处理模式优先级、来源失败计数与在线证据。失败或取消不推进最后成功采样时间。只有电量数值未变化时可省略数字重绘。

## 9. 数据模型

字段与契约见 [AGENTS.md §5.3–5.4](../AGENTS.md#53-核心契约与数据模型)。`DeviceKey` 用于持久身份，`ReadingKey` 区分采集来源及端点。保留各来源最近的有效读数，再按 D4 裁决。
历史日文件用 UTC 日期命名，每条记录带 `DeviceKey`。每设备每 5 分钟桶只接受首条在线有效样本，重启后恢复桶索引，断连缺桶留空。
设置使用同目录临时文件，首次写入原子移动，后续用 `File.Replace` 留备份。串行写入且回读一致后广播，损坏文件留诊断记录并尝试恢复上一次有效配置。

## 10. 外壳与视觉实现约束（设计稿必须让步的地方）

这几条都是 VT9 上实测踩出来的，直接作为设计约束写死：

1. **主窗口按 8 DIP 设计**，挂件按 D10 自绘圆角。DWM 属性 33 只有 DONOTROUND / ROUND(8 DIP) / ROUNDSMALL(4 DIP) 三档，设计稿的 24 无法用系统 API 实现。做法：`WindowCornerRadius = 8`，内层 `Border.CornerRadius` 引用同值，并给 surface 加同半径 `RectangleGeometry` 裁剪——`Border.CornerRadius` 不裁 Child，不裁就会出现直角蒙层盖住圆弧、露出双层圆角的假象。
2. **Acrylic 每次显示都要重做帧扩展**，并 `SetWindowPos(SWP_FRAMECHANGED)` 逼 DWM 重算窗框。否则“先创建后显示”的路径（自启、隐藏后显示）会整窗变成不透明灰板。
3. **不要按焦点切换底色兜底**。判据只认 `DwmGetWindowAttribute(hwnd, 38) == 3`，失焦铺实色正是灰板来源。
4. **挂件窗口**：`WS_EX_TOOLWINDOW | WS_EX_NOACTIVATE`，不进 Alt+Tab，`WM_MOUSEACTIVATE` 返回 `MA_NOACTIVATE`；贴边吸附阈值 12px，吸附后记住位置。
5. **托盘图标**：验证任务栏溢出区、手动固定与 Explorer 重启恢复。托盘不可用时关窗即退出。
6. **单实例**：Mutex 与命名管道按用户和会话隔离。二启尝试向主实例 PID 授权后再发激活消息。连接等待与应答设上限，系统拒绝置前时给提示。
7. **抓屏验收判据**：四角色值各不相同 = 透出壁纸；四角同一常数 = 实色填充。取窗口内 (6,6) 会落在 DWM 阴影带（恒 165 灰），是误判源。

## 13. 实施路线

| 阶段 | 内容 | 出口条件 |
| --- | --- | --- |
| S0 骨架 | 单实例、托盘、主窗口空壳、SettingsStore、`--self-test` 框架 | 二启唤醒正常、托盘图标可见可固定、自检跑通 |

## 14. 风险登记

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| BLE GATT 连接抖动 / 系统级缓存失效 | 电量更新停滞 | 会话缓存 + 指数退避 + 60s 兜底 + 详情页显示“数据滞后 N 分钟” |
| 设备休眠被误判离线 | 用户投诉误报 | 分来源计数、记录最后成功采样并区分在线与未知 |
| 同一设备多路径枚举导致重复项 | 列表重复 | 物理设备键与来源键分离，可信映射后再裁决 |
| Win11 版本差异（托盘抽屉、圆角、Acrylic） | 表现不一致 | 能力探测 + 降级路径，不自适应就显式降级并在设置页标注 |
| 厂商协议需要常驻句柄，与官方驱动冲突 | 设备功能失效 | 短连接 + 只在用户启用插件时打开；冲突时禁用插件并说明 |
| 自包含包体和首次解包 | 分发或首帧超标 | 按 D16 实测未裁剪发布包，超过上限时重新评审 |

## 15. 待确认

1. **产品名与仓库名**：工作区叫 BatteryManagement，设计稿叫 PowerDock，命名需统一（建议对外 PowerDock，内部沿用目录名）。
2. **发布口径**：确认包体上限、最低支持 Windows 版本和材质降级范围。
3. **首发设备范围**：只覆盖 1 台蓝牙耳机 + 1 只 HID 鼠标 + 本机电池做验证，还是要求一次性支持多品牌？
4. **Widgets Board 是否必须**：若必须，项目要从“绿色免安装”改为 MSIX 打包，架构影响很大，需提前定。
5. **是否需要设计稿同步改版**：第 10 节的 7 条约束里，圆角（24→8）与 Widgets Board 延期会直接改变设计稿，要不要出一版 v2 画板。
