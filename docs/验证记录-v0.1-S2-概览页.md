## 一、做了什么

1. **四页并行集成与生命周期契约**：
   - 更新 `AGENTS.md` (§6.4.2、§6.5、§18) 并出具 `docs/四页集成接入规范.md`；
   - 确立集成人独占接线（`MainWindow.cs`、`MainWindow.DeviceContent.cs`、`App.cs`、`MainWindow.OverviewContent.cs`），另外三个页面独立成单独视图文件；
   - 统一遵循 `MainPage`、`MainPageContentFactory`、`MainWindow.ReplacePageContent(page, content)` 规范，每页只注册一次；
   - 统一消费 `AcquisitionHost` 单例快照 `IReadOnlyList<DeviceState>` 与单例 `SettingsStore`，严禁每页私建采集器或设置副本；
   - 严格约束采集与快照回调**严禁直接改写 `_contentHost.Content`**，切页与内容呈现唯一受导航状态机控制。

2. **跨页设备定位接口契约**：
   - 定义 `IDeviceLocator` 接口（`SelectAndScrollToDevice(DeviceKey key)` / `SelectAndScrollToDevice(string key)`）；
   - 在 `DeviceSummaryView` 实现 `IDeviceLocator`，支持行高亮与滚动定位；
   - `MainWindow` 新增 `NavigateToDevice(DeviceKey key)`，负责切到设备页并路由定位，与设备管理页实现方对齐。

3. **概览页（方案 A）聚合计算引擎（`OverviewAggregator.cs`）**：
   - 在 `PowerDock.Core.State` 中实现纯计算逻辑，处理状态带四格、焦点设备优先级、7 天趋势样本聚合与空态判据；
   - **严格过滤未知值**：`Percent == null` 的未知电量与离线无读数设备不参与最低电量与需充电判定；真实 `0%` 仍为有效读数；
   - **焦点设备优先级**：需充电 > 正在充 > 离线 > 正常有效最低电量 > 首台；
   - **7 天趋势柱状图**：支持历史样本聚合，若无历史数据如实标记 `HasTrendHistory = false` 进入趋势空态；断连区间计算 3px 短桩（gap），连线不插值，周日到周六 7 列排列，今天高亮。

4. **概览页（方案 A）WPF 视图（`OverviewView.cs`）**：
   - 纯代码构建（无 XAML 依赖），完整还原 HTML 稿方案 A 与视觉 Token（`--accent`, `--ok`, `--warn`, `--danger`, `--off`, `--hair`, `--track`）；
   - **第一层（状态带四格）**：
     - 需充电（整屏唯一红格）：仅在需充电台数 > 0 时启用 `ovcell--alert` 危险红描边与淡底，为 0 时呈现普通中性格；
     - 充电中：统计正在充电台数与首要充电设备百分比；
     - 在线：`在线数 / 总数` 与离线设备摘要；
     - 在组件：`已勾选数 / 总数` 与规格上限说明。
   - **第二层（焦点区）**：
     - 左侧最需要关注设备：36px ExtraBold 大字百分比（缺失显示「—」）、设备名称、状态/链路/时效/低电阈值元数据；
     - 近 7 天趋势：无历史数据时显示明确的「暂无 7 天趋势数据 · 历史样本积累中」空态；有样本时渲染 7 列柱状条与 gap 短桩；点击焦点卡跳转设备页定位；
     - 右侧另外 2 台要注意：展示至多 2 台充电中/离线/偏低设备，第 3 行汇总「其余 N 台 · 正常 · 最低 M%」，底部标注「全部 N 台见『设备』页」。
   - **第三层（全貌设备条）**：
     - 全部设备横向等宽排成柱状条（基线 1px track，高度按百分比缩放）；
     - 柱顶显示百分比与语义色，柱底显示设备名称；
     - 点击任一设备柱触发 `NavigateToDevice` 跳转设备页定位。
   - **第四层（全局空态）**：
     - 快照为空（0 台设备）时，中间与底部折叠，展示规范的居中指引卡片（「未发现设备」，引导检查蓝牙与系统配对），绝不虚构 0%。

5. **诊断与自动化测试**：
   - 新增 `tests/PowerDock.Core.Tests/OverviewAggregatorTests.cs`（7 条高覆盖率单测）；
   - 新增 `--diagnose-overview` 实机交互诊断套件（10 项断言，直出 `data/overview-diagnose.json`）。

## 三、哪些没验

按照仓库 §15 交付规则，诚实记录未经验证项及原因：

1. **100% DPI 实机显示**：
   - **未验证**。本机仅有 1 台 2560×1440 @ 150% 显示器，无 100% 会话环境可切；
   - **解除条件**：在原生 100% DPI 显示器或虚拟显示屏上运行 `--diagnose-overview`，确认 `OV-DIAG-02` 报 `1.00x1.00` 且各控件无遮挡。

2. **真实硬件连续 7 天长周期样本趋势**：
   - **未验证**。目前系统处于 S2 界面阶段，真实的 7 天持久化历史落盘（`HistoryStore`）规划在 S3 阶段实施；
   - 本轮趋势仅在「真实样本注入」与「无数据趋势空态」两个逻辑分支上通过了实机诊断验证。长周期真实采样需留到 S3 打磨期闭环。

3. **标题栏真实物理鼠标拖动**：
   - **未验证**。合成输入在独立桌面不可信，仍依赖人工物理鼠标拖动验证。
