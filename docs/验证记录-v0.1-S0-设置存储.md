### 1.2 两处必要调整

1. **测试工程 TFM `net10.0` → `net10.0-windows`**：用例要用 `DirectoryInfo.GetAccessControl()` /
   `FileSystemAccessRule` / `WindowsIdentity` 注入「目录拒绝写入」，这些 API 带 `[SupportedOSPlatform("windows")]`，
   在 `net10.0` 下会产生 CA1416 警告。测试本身只在 Windows 上跑，改后 `build.ps1` 仍 0 警告（见 2.1）。
2. **用例取值一律非默认**（v1 = `dark/15/large`，v2 = `light/12/small`，默认是 `dark/20/medium`）。
   原因见 2.4：用默认值做 v1 时，「回滚成功」与「回落到默认配置」在断言上不可区分，用例会假通过。

### 2.4 踩过的坑（写下来防止复用错误做法）

1. **取值必须有区分度**：最初 v1 用了 `dark/20`（等于默认配置），M2 变异把恢复分支删掉，用例仍然全绿
   —— 因为「恢复到 v1」与「回落到默认值」得到相同断言结果。改成 `dark/15/large` 后 M2 立刻变红。
2. **`[IO.File]` 不信 PowerShell 的相对路径**：变异脚本里用 `[IO.File]::ReadAllText('src\...')` 时，
   它按**进程 CWD**（工作区根）解析，导致变异写进了共享检出 `E:\project\BatteryManagement` 而不是 worktree，
   两次变异都「没红」其实是变异根本没进被测工程。已 `git checkout` 还原共享检出并核验 `git status`；
   之后所有变异一律用**绝对路径**。教训：多 worktree 并行时，脚本里的相对路径必须显式 `Set-Location` 或改绝对路径。

## 3. 哪些没验

1. **满盘 / ENOSPC 注入（任务第 3 条）——未做，这是本矩阵项唯一缺口**。
   本机为**非管理员**，无法 `Mount-DiskImage` 建小容量 VHD/RAM 卷，也没有可写满的目标卷；
   而产品侧没有 `FileSystem` 抽象接缝（`AtomicFile` 直接调 `File.*`），无法在不改产品代码的前提下注入 `ERROR_DISK_FULL`。
   **解除条件**（任选其一）：① 管理员权限下建 32–64MB VHD/RAM 卷并把目标指到该卷写满；
   ② 给 `AtomicFile` 引入可注入的文件系统抽象（属产品改动，需另立 PR 并重跑本记录）；
   ③ 用支持 IO 故障注入的测试环境（如带磁盘配额的容器）。
   注：满盘与第 1/2/3 条走的是**同一个** `catch → Rollback → throw` 代码块，异常类型同为 `IOException` 家族，
   但「同代码块」不等于「已实测满盘」，故如实标未验。
2. **断电/崩溃一致性**：`File.Replace` 在 NTFS 上的持久化与元数据顺序未做崩溃注入（需要 VM 冷断电或驱动器级故障注入）。
   目前只证明「进程内失败会回滚」，不证明「掉电后磁盘一定还是上一版」。
3. **跨进程并发写**：`_syncLock` 只保证**单进程内**串行；两个 PowerDock 实例同时对同一 `settings.json` 调 `Save`
   会互相覆盖（无跨进程文件锁）。单实例设计下风险低，但外置路径/多用户场景未验证。
4. **网络盘（SMB）上的 `File.Replace` 语义**：UNC 路径下替换/备份行为未测（`File.Replace` 在部分 SMB 实现上会失败）。
5. **失败消息的本地化**：ACL 用例只断言 `Access to the path`（稳定片段），未断言完整中文/英文消息；
   非英文系统上的日志文案未验。
6. **只读目录的另一种形态**：本记录用 ACL `Deny` 模拟「目录不可写」；Windows 的目录 `ReadOnly` 属性
   （资源管理器「只读」勾选框）**不阻止**文件创建，未作为失败条件（也不用它冒充）。
7. **矩阵其他行的时效**：本记录只按授权更新 `S0-STORE-02`。矩阵里 `S0-TEST-01`（写「`tests/` 0 文件」）、
   `S0-STORE-01`（证据等级写「异常分支未覆盖」）、`S0-PACK-01`/`S0-BUILD-02`（写 csc.exe 基线）等行
   是基于 `bc822b5` 的复验结论，PR-S0-01 合并后事实已变，**需 qa-release 复核后改判**，本 PR 不代改。
