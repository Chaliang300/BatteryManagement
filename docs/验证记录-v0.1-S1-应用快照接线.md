## 1. 做了什么

1. **本机电池采集实现（`WmiBatteryProvider.cs`）**：
   - 只读查询 `Win32_Battery`（`Name`、`EstimatedChargeRemaining`、`BatteryStatus`）。
   - 落实 **D5 契约**：独立只读查询充电状态（`BatteryStatus` 码值 6/7/8/9 判定为充电中），绝不按电量上涨趋势猜测。
   - 链路固定为 `Internal`（本机电池），异常或缺失时如实归因，不补 0%。

2. **采集运行时与应用宿主（`AcquisitionRuntime.cs` / `AcquisitionHost.cs`）**：
   - `AcquisitionRuntime`：统一装配 WMI、HID、BLE 三大 Provider；按 D9 周期（可见空闲 60s）执行后台兜底刷新；提供 `RefreshNowAsync` 单次防重叠全量刷新入口。
   - `AcquisitionHost`：订阅 `DeviceStateService.SnapshotUpdated`，所有 UI 消费统一经 Dispatcher 派发，采集后台线程绝不直触控件；支持快照订阅即时回放。

3. **托盘最低电量聚合与固定 100% 根除（`TrayAggregator.cs` / `TrayIconService.cs`）**：
   - 落实 **C9 裁决**：彻底删除托盘写死 `100%` 初始值，无读数时更新为 `null`（未知态）。
   - 托盘按 **P0-2 / D14** 聚合：取在场全部设备的最低电量；充电标志与离线状态跟随该最低电量设备；全无有效读数时 Tooltip 显示「N 台设备，电量未知」，绝不以 0% 充数；真实 0% 保留为有效最低读数。
   - 托盘右键菜单「刷新设备」接通 `AcquisitionHost.RefreshNowAsync` 真实全量采集，告别假刷新。

4. **主窗口设备内容挂载（`DeviceSummaryView.cs` / `MainWindow.DeviceContent.cs`）**：
   - 实现 `DeviceSummaryView`：消费同一份快照，显示设备名称、链路类型、在线状态点、电量读数与原因说明；身份未确认、来源冲突、读数过期均在行内标注。
   - 无设备时展示明确空态指引（「未发现设备」「检查蓝牙开启与配对」「确认 USB/2.4G 接收器已插入」），不显示虚构电量。
   - 采用 partial class 扩展 `MainWindow.DeviceContent.cs` 挂载到现有 `_contentHost`，不破坏既有窗口视觉树与 Acrylic 材质。

5. **读取诊断命令（`--diagnose-read <秒数>` / `ReadDiagnostics.cs` / `ReadDiagnosticsRunner.cs`）**：
   - 无界面采集采样，输出逐事件 JSONL（`events.jsonl`）与摘要（`summary.json`）。
   - 详细记录设备发现、链路依据、在线状态、读数来源、失败类别、状态变更次数以及进程内首读耗时（`first_read_ms`）。
   - 硬件序列号与蓝牙 MAC 地址在输出中自动脱敏。

### 2.3 托盘与应用回归

- 启动时托盘初始读数：不再是固定 100%，显示「PowerDock - 电量未知」；
- 采集上报后：自动聚合最低电量（80% 本机电池），Tooltip 变为「本机电池 - 80%」；
- 托盘右键「刷新设备」：触发全量刷新，日志输出 `[INFO] Manual refresh requested from tray.`；
- 主窗口关闭到托盘与激活：`--diagnose-close-tray`、`--diagnose-window`、`--self-test` 保持全部通过。

## 3. 哪些没验

1. **真实标准 HID 0x06:0x20 样机首读**：本机缺少暴露标准电量字段的 HID 设备，该链路在实机中如实显示「—」并注明 `access_denied` 或 `no_standard_battery_usage`，实机 ≤3s 首读标「未验证」（见 S1 验收清单 §4）。
2. **同型号第二台 BLE 外设**：本机仅有 1 台 Kzzi 键盘、1 台 Xbox 手柄、1 台 VGN 键盘，型号互异，同型号多台不合并场景标「未验证」。
3. **断连重连后别名串流测试**：别名持久化配置存储在 S0 已验证，模式切换别名绑定需结合 S2 界面进行长周期验证。
