## 1. 做了什么

1. **后端抽象与状态机解耦（`IBluetoothBackend.cs` / `BluetoothDeviceProvider.cs`）**：
   - 抽象 `IBluetoothBackend`，将 WinRT 投影细节封装在采集层内部，实现纯逻辑 `BluetoothDeviceProvider`，保证在无蓝牙硬件的构建环境与单测中 100% 可测。
   - 落实 **C10 契约**：严格分开记录「已配对（`IsPaired`）」与「当前连接（`IsConnected`）」。已配对但断开的设备完整保留在设备列表与快照中，链路标明 `Bluetooth`，状态如实标为 `Offline`，绝不虚构 0% 读数；断开期间不发起无效的 GATT 连接探测。
   - 已连接但无电池服务：设备保持 `Online`，百分比为 `null`，明确归因 `NoBatteryService`。
   - 订阅与通知：特征支持 `GattCharacteristicProperties.Notify` 时自动订阅 `ValueChanged`，电量变化即时推送 `ReadingUpdated`；不支持时标记 `SupportsNotify=false` 由外部调度轮询。
   - 适配器不可用：监听到 Radio 关闭或 Watcher 异常停止时，发布 `SourceUnavailable` 事件，保留已缓存设备条目与读数，界面标记过期，不发生清空闪烁。
   - 刷新串行化：同一 `ReadingKey` 使用 `SemaphoreSlim` 保护；每次断开/重扫递增会话版本号，丢弃旧会话延迟到达的读取回调，避免将离线设备重新标为在线。

2. **真实 WinRT 蓝牙后端（`WinRtBluetoothBackend.cs` / `PowerDock.Providers.Bluetooth`）**：
   - 采用 `net10.0-windows10.0.19041.0` 目标框架编译，使用 `Windows.Devices.Bluetooth` 与 `Windows.Devices.Enumeration` 原生投影。
   - 使用 `DeviceInformation.CreateWatcher` 监听已配对 BLE 设备，显式请求 `System.Devices.Aep.IsPaired`、`System.Devices.ContainerId` 与 `System.Devices.Aep.Bluetooth.Address` 属性。
   - **修复 Windows AEP 属性缺陷**：实测发现 `AssociationEndpoint` 的 `DeviceInformation.Pairing.IsPaired` 恒为 `false`，导致已配对设备全被误判为未配对；已修正为读取 AEP 专用属性 `System.Devices.Aep.IsPaired`，并退回选择器语义校验。
   - 短连接与句柄生命周期管理：每次读取后显式释放 `GattDeviceService` 与 `BluetoothLEDevice`，并在 `Dispose` 中注销监听器，彻底解决 GATT 会话句柄随轮询持续增长的问题。

3. **诊断标识脱敏（`DiagnosticRedaction.cs`）**：
   - 蓝牙 MAC 地址与 DeviceId 脱敏为 `***` + 末尾 4 位，对外提交的日志与摘要不外泄真实硬件地址。

### 2.2 本机硬件实机探测（L3 真机证据）

运行环境：ASUS TUF Gaming F15 (FX507VV)，Windows 11 Build 26220，Intel Bluetooth Radio (`USB\VID_8087&PID_0026`)。

1. **设备发现与状态识别**：
   - `Kzzi-i75 5.0`（键盘）：识别为已配对、已连接（`Connected`），容器 ID 匹配。
   - `Xbox Wireless Controller`（手柄）：识别为已配对、已断开（`Disconnected`），连接状态 `Offline`，未虚构 0%。
   - `VGN V98pro BT1`（键盘）：识别为已配对、已断开（`Disconnected`），连接状态 `Offline`，未虚构 0%。

2. **冷启动首读性能**：
   - 进程内 `Stopwatch` 测量（口径 B）：从探测启动到 `Kzzi-i75` 首条 `Percent=100`（`0x2A19` 读数）到达，耗时 **7,191 ms**。
   - 满足 `AGENTS.md` §3 P0-1 指标口径（BLE 冷启动首读 **≤ 10s**）。

3. **资源释放与稳定性验证**：
   - 连续进行 30 轮 GATT 电量读取，每次读取耗时稳定在 2.6s–3.1s。
   - 30 轮读取后触发垃圾回收，进程句柄数稳定在 **384–385**，未发生 GATT 会话句柄泄漏。

## 3. 哪些没验

1. **连续 5 分钟高频不间断轮询**：实机验证了连续 30 轮主动读取与句柄稳定，但未在实机上维持 300 秒持续后台采样。
2. **物理断连与重新连接恢复演练**：通过单测覆盖了状态切换，未在实机上物理关闭/开启键盘电源进行波形捕获。
3. **关闭蓝牙无线电（Radio State Off）实机演练**：关闭系统无线电属系统状态破坏性操作，未在实机上执行，相关行为由单测 `AdapterUnavailable` 覆盖。
4. **经典蓝牙设备（如 AirPods Pro）**：通过 A2DP/HFP 连接的经典蓝牙不暴露标准 GATT 0x180F 服务，按契约不包含在 S1 BLE GATT 首发范围内，单列为未验证。
