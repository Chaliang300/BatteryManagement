## 1. 证据分级（判定前先定级）

| 级别 | 名称 | 判据（一句话） | 证据上限 |
| --- | --- | --- | --- |
| L0 | 代码检查 | 只读源码/文档，确认某段实现或某个常量存在；不产生运行行为证据 | 只能证明「存在」，不能证明「生效」 |
| L1 | 模拟测试 | 在真实进程内用构造对象或测试开关（如 `forceFailureForTest`）走通某个分支；不跨进程、不跨用户环境 | 不能外推到「真实环境亦如此」 |
| L2 | 单元测试 | 自动化、可重复、覆盖输入/输出与异常分支的断言（xUnit 等），有失败即失败 | 只覆盖被断言的分支 |
| L3 | 实机测试 | 真实进程 / 真实窗口 / 真实系统状态，留下可复现观测值（PID、坐标、像素、注册表、日志、模块表） | 可判该场景通过 |
| L4 | 发布验证 | 在目标分发形态（自包含包、无目标运行时的目标机、目标 Windows 版本）上从零运行，记录包体、解包位置、首帧 | 只有 L4 能判「可发布」 |

**判级规则**

1. 该行验收口径所要求的最低级别 > 实际证据级别 → 状态必须为 `未验证`，不得因「逻辑上应该对」判通过。
2. 同一结论需要两条不同证据共同支撑时（例：Acrylic 需 L3 像素 + L3 `HRESULT`），必须在证据列写明「合并判据」，缺一即为 `未验证`。
3. 代理指标必须自带明确的指标定义，不得命名为「首帧」「启动耗时」等既有口径。

## 4. 本轮不得升格的口径（硬约束）

以下五条是本轮审计中实际出现过的「证据级升格」，后续任何验证记录都不得再犯：

| # | 禁止的等价替换 | 为什么不等价 | 正确判法 |
| --- | --- | --- | --- |
| ① | **同进程 Mutex ≠ 二启** | 同一进程内 `new Mutex(true,name,out createdNew)` 第二次必得 `createdNew=false`，这只是内核对象语义，未跨越进程/会话/权限边界 | 必须两个真实进程，留下二启 PID、退出码、主实例激活日志 |
| ② | **`Visible=true` ≠ 图标可见** | WinForms `NotifyIcon.Visible` 不校验 `Shell_NotifyIcon` 返回值；失败时也会静默 | 用 `Shell_NotifyIconGetRect` 拿到落在通知区域的矩形，或人工确认后再判 |
| ③ | **API 能力 `True` ≠ Acrylic 呈现；`HRESULT=0` 也不等于材质可见** | `SupportsAcrylicBackdrop()` 只比较 Build ≥ 22621；本轮实测属性 38=3 设置成功、`hr=0`，但像素透射恒为 0（被 WPF 合成遮挡） | 以**像素透射**为主证（背板亮度阶梯），`HRESULT` 仅作补强；两者不一致时以像素为准 |
| ④ | **进程运行时长 ≠ 首帧** | `--self-test` 路径不创建窗口，`uptime` 是「CLR 加载 + 前 13 项自检」的累计 | 从进入 `Main` 到首个 `CompositionTarget.Rendering` 的差 |
| ⑤ | **封装存在 ≠ 已触发** | `FlashWindowEx` / `ApplyMainWindowStyle` / 降级分支写好了不等于被执行过 | 构造触发条件并观测，或记录该路径的执行标记 |
| ⑥ | **抓屏拿到像素 ≠ 像素可信** | 本轮实测当前会话的抓屏管线**不再包含子窗口**：`GetWindowRect` 有效但抓到的是 (140,148,141) 固定值、自建纯色窗口不出现、`FG_SET_OK=False` | 任何像素证据必须先过「已知纯色窗口抓屏对照」；对照不通过则整张像素证据作废，改用窗口内自绘/位图直出 |

## 6. 证据路径与复现命令

证据根目录：`%LOCALAPPDATA%\Programs\PowerDock-qa\`（本轮为 `bc822b5` 的取证；后续每 commit 新建 `<commit7>\` 子目录，不混用）

| 证据 | 位置 |
| --- | --- |
| 旧产物复跑 JSON | `…\PowerDock-qa\data\self-test.json`（3,766 B） |
| 真实二启 / 并发二启日志 | `…\PowerDock-qa\powerdock.log` |
| 窗口抓屏（含背景带） | `…\PowerDock-qa\cap-fullscreen.png`（2,560×1,440 物理像素） |
| 窗口本体 | `…\PowerDock-qa\cap-window.png` |
| 角部 4× 放大 | `…\PowerDock-qa\cap-corner-4x.png` |

关键复现命令：

```powershell
# 1. 干净检出构建
git clone --no-hardlinks <repo> $env:TEMP\pd-clean; cd $env:TEMP\pd-clean
powershell -NoProfile -ExecutionPolicy Bypass -File .\build.ps1

# 2. 自检复跑（必须放在工作区外，避免沙箱降权）
$dst="$env:LOCALAPPDATA\Programs\PowerDock-qa"
Copy-Item .\PowerDock.exe $dst -Force
Measure-Command { & "$dst\PowerDock.exe" --self-test }

# 3. 真实二启（先清场：同 Session 多 agent 会互抢 Local\PowerDock_Mutex_<sid>）
Get-Process PowerDock -ErrorAction SilentlyContinue | Stop-Process -Force
$p1 = Start-Process "$dst\PowerDock.exe" -PassThru; Start-Sleep 2
$p2 = Start-Process "$dst\PowerDock.exe" -PassThru; $p2.WaitForExit(6000)
"second exit=$($p2.ExitCode)  alive=$(@(Get-Process PowerDock).Count)"

# 4. 窗口几何（必须 DPI-aware 取物理像素，再除以缩放比）
Add-Type -AssemblyName System.Drawing
# 见本文件 §2 S0-WIN-01 实测值；GetDpiForWindow=144 → 1320/1.5=880、900/1.5=600
```

> 环境陷阱备忘：`GetWindowRect` 在 DPI-unaware 调用方下返回**虚拟化坐标**（会得到 880×600 而误以为单位是物理像素）；判 DPI 一律用 `DwmGetWindowAttribute(DWMWA_EXTENDED_FRAME_BOUNDS)` + `GetDpiForWindow`。
