## 1. 做了什么

1. **契约文档修订（文档先行，AGENTS.md）**：
   - §2.1 新增 C8：作废「顶层 `HidP_GetCaps` 未命中作为缺少标准电量判据」，改查 Input/Feature 值能力（`HIDP_VALUE_CAPS`）。
   - §2.1 新增 C9：删除托盘写死 `100%` 初始值，无读数时呈未知态，真实 0% 保留为有效读数。
   - §2.1 新增 C10：蓝牙「已配对」与「当前连接」分别记录，配对为清单资格，连接为在线判据；已配对但断开不补 0%。
   - §3 P0-1 强调：先正确识别身份、链路、在线状态，再谈电量；读不到显示「—」并注明原因。
   - §5.3.1 确立「身份、链路、在线状态、电量」四者独立契约与硬约束。

2. **设备与链路数据模型（PowerDock.Core）**：
   - `DeviceIdentity`：以 Windows 容器 ID 为持久 `DeviceKey`，拒绝 `00000000-0000-0000-ffff-ffffffffffff` 等哨兵；无容器时退回 `FromFallback` 并标 `IsContainerVerified=false`；仅凭 VID/PID、名称、型号相同不得合并。
   - `LinkInfo`：`LinkKind`（Bluetooth / Wireless24G / UsbWired / Internal / Unknown）；四判断独立（`IsPaired` / `IsConnected` / 外设在线 / `PercentUnavailableReason`）；严守「USB 父节点只是总线证据」，只能确认接收器时标 `IsReceiverOnly=true`（外设未知），仅知总线时显示「USB 设备，连接方式待确认」。
   - `ProviderDevice`：只接受 0–100 百分比或 null；null 必须带 `PercentUnavailableReason`；真实 0% 是有效读数。
   - `SourceReading`：按 `ReadingKey` 保留各来源最新读数、连续失败数与时效。
   - `DeviceState`：包含身份验证标记、链路依据、时效状态、来源列表与不可用原因。

3. **裁决与快照状态服务**：
   - `SourceArbiter`：严格按 D4 权威序（`Vendor > BluetoothGatt > Hid > Wmi`）裁决；差值 >5% 标 `HasConflict`，差值 ≤5% 不标冲突；支持每来源独立时效窗口，过期保留数值供界面「N 分钟前」显示，同时标记 `IsPercentStale`。
   - `LinkArbiter`：多端点同机归并（如 BLE 外设与 HOGP HID 接口）时显式裁决链路，连接态蓝牙 > 有线 > 接收器 > 未知。
   - `DeviceRegistry`：只按 `DeviceKey` 归并，支持多 ReadingKey。
   - `DeviceStateService`：200ms 合并快照广播；三态判定（在线/离线/未知）；匿名回退名不覆盖真实外设名（`IsMoreSpecificName`）；提供 `RefreshAllAsync` 真实刷新接口。

## 3. 哪些没验

1. **真实硬件 P/Invoke 读取**：本 PR 为纯逻辑契约与状态服务层，不含 Win32/SetupAPI/WinRT 具体采集器实现，未接触物理设备句柄（属后续 HID 与 BLE PR 范围）。
2. **多线程并发极限压力**：进行了 `SemaphoreSlim` 串行与锁保护单测，但未在 1000+ 虚拟端点高频洪峰下做并发压力测试。
3. **跨进程 / 跨机器**：单测仅在当前进程运行，未进行多用户会话隔离验证（本层无跨进程状态）。
