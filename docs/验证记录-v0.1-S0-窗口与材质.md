## 〇、修复前基线（"红"的证据，先固定再修）

- QA 背板阶梯法（lock 前）：背板 0→255 共 9 档，窗口内部 luma **恒 20.008、spread 0.000**；α235 下 backdrop=255 应得 ≈ **38.43**，实测 20.01 → **透射率 0**。
- 本审计独立回归（隐藏/显示前后帧）：内部 luma 20.01±0.36，背板 32.8±44.3（含 121 个 166–250 亮样本），回归斜率 **-0.0001 / R²=0.0004**。
- DWM 属性回读 33=2 / 38=3 / 20=1 且 HR=0 → 属性设置成功但 WPF 合成目标不透明，材质被遮挡。基线结论：**透射 0，非 7.84%**。

## 一、做了什么

1. **`CompositionTarget.BackgroundColor = Colors.Transparent`**（`WindowBackdropController.OnSourceInitialized`）：修复 WPF `HwndTarget` 不透明合成（头号真因）。
2. **返回值检查 + 回读**（`DwmHelper` 重写）：`DwmExtendFrameIntoClientArea` 必须返回 0；`DwmSetWindowAttribute` 记录 HRESULT；`DwmGetWindowAttribute` 回读 corner/dark/backdrop 属性（不再"设了不验"）。
3. **分帧激活**：先设 `backdrop=NONE(1)`，250ms 后的独立 DispatcherTimer 合成帧再设 `Acrylic(3)`；每次重绑都会重新走该序列。
4. **重做帧扩展的时机补齐**：`SourceInitialized` / `ContentRendered` / `IsVisibleChanged(visible)` / `WM_DWMCOMPOSITIONCHANGED` / `WM_THEMECHANGED` / `WM_SETTINGCHANGE`，**每次显示都重做**（§7.3）；`IsVisibleChanged(false)` 取消分帧定时器。
5. **降级路径**：DWM 合成关闭 / `EnableTransparency=0` / 高对比度 / `AllowsTransparency=true` / Build<22621 / `CompositionTarget` 不透明 → 记录原因并切换到**明确静态底**（同 RGB 不透明 `#14161C`），材质未就绪前表面也保持不透明，避免灰板。
6. **首帧埋点（`FirstFrameTimer`）**：`Program.Main` 首行 `Arm()`；`MainWindow` 订阅首个 `CompositionTarget.Rendering` 并 `NotifyFirstFrame()`；记录 elapsedMs / build / round / osBuild / session / pid；`PERF-01` 明确改为 **uptime（非首帧）**，新增 `PERF-02` 验证埋点通路（自检无窗口不产生数值）。
7. **`SYS-02`**：判据改为 `osMajor>=10 && build>=22000`，区分 Win10/Win11。
8. **`FS-01`**：描述已在 PR-S0-04 对齐为「数据目录写入/读取/删除闭环测试（原子覆盖由 FS-02 验证）」；本 PR 未再改实现（理由：原子替换由 FS-02 真正覆盖，FS-01 不应冒充原子）。
9. **诊断入口**：`--diagnose-window`（HRESULT/回读/分帧时序/隐藏-显示重做）、`--diagnose-window-fallback`（强制降级）、`--diagnose-first-frame`（真实首帧测量）。
10. **α 数值未改**：根 surface 仍 α235；材质就绪时才切回 α235 表面，降级时只把同一 RGB 换为不透明。

## 二、怎么验的（锁屏下可执行部分）

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\build.ps1   # 0 错误 / 0 警告
dotnet test .\PowerDock.sln                                      # 12/12 通过
PowerDock.exe --self-test                                        # 15/15 通过
PowerDock.exe --diagnose-window                                  # exit 0
PowerDock.exe --diagnose-window-fallback                         # exit 0
PowerDock.exe --diagnose-first-frame                             # exit 0（数值锁屏下不可信）
```

- **`--diagnose-window`（材质路径，锁屏实测）**：`compositionTargetTransparent=true`、`corner hr=0/readback=2`、`dark hr=0/readback=1`、`ExtendFrame(-1) hr=0`、`NONE hr=0/readback=1`、`staged acrylic hr=0/readback=3`、`MATERIAL READY`；隐藏→显示后 `rebindCount` 由 3 增至 **4**，事件含 `IsVisibleChanged(visible)` 且再次出现 `ExtendFrame(-1) hr=0` + `staged Acrylic` → **§7.3 每次显示重做已生效**。
- **真实系统透明关闭**：读取 `HKCU\...\Personalize\EnableTransparency=1` → 置 0 → `--diagnose-window` 返回 **exit 0**，`fallbackActive=true`、`materialReady=false`、`lastReason=system transparency disabled (EnableTransparency=0)`、`surface=opaque(fallback)`；随后恢复原值 1（已确认恢复）。`WM_SETTINGCHANGE` 还触发多次 rebind（日志可见）。
- **强制降级**：`--diagnose-window-fallback` → exit 0，`fallbackActive=true`、`materialReady=false`、理由 `diagnostic ForceFallback`。
- **首帧埋点**：`--diagnose-first-frame` → `measured=true`、`elapsedMs≈326.79`、`build=Debug`、`round=1`、`osBuild=26220`；**锁屏下渲染节拍不可信，只证埋点通路已通**，真实数值待解锁复测。
- **自检**：15/15（新增 PERF-02；SYS-02 判 Win11/26220 通过；PERF-01 明确标注 uptime；FS-01 描述与实现一致）。

## 三、哪些没验（待解锁）

1. **透射率复测（唯一材质判据）**：背板 0→255 阶梯，须先过**纯色窗口抓屏对照**（§9 陷阱），窗口内部 luma 斜率 ≈ **0.0784±容差**、**R²>0.95**；backdrop=255 时内部 luma 应从基线 20.01 升到 **≈38.43**。当前只完成合成链修复与属性证据，**未重新测透射，不能写"Acrylic 已呈现"**。
2. **首帧真实耗时**：锁屏下 326.79ms 不可信；解锁后以 `--diagnose-first-frame` 在交互桌面复测，记录机型/构建类型/轮次。
3. **"降级不变灰板"的像素证据**：降级分支已真实构造（`EnableTransparency=0`）并观测到静态表面，但锁屏抓屏不可信；解锁后补"纯色/静态底"截图对照。
4. **材质呈现后的视觉确认**：圆角/材质/主窗口画面的解锁后像素复核。

## 四、备注

- α235 的透射率判据是**可计算的**：`0.0784×backdrop + 0.9216×surface`；backdrop=255 时内部 luma 期望 ≈38.43，与修复前 20.01 的差值 18.42 即"透射为 0"的量化证据。
- 本轮所有结论均按"先基线、后修复、再复测"顺序记录；未用锁屏下的属性成功代替材质呈现。
