## 〇、修复前基线（"红"的证据，先固定再修）

- QA 背板阶梯法（lock 前）：背板 0→255 共 9 档，窗口内部 luma **恒 20.008、spread 0.000**；α235 下 backdrop=255 应得 ≈ **38.43**，实测 20.01 → **透射率 0**。
- 本审计独立回归（隐藏/显示前后帧）：内部 luma 20.01±0.36，背板 32.8±44.3（含 121 个 166–250 亮样本），回归斜率 **-0.0001 / R²=0.0004**。
- DWM 属性回读 33=2 / 38=3 / 20=1 且 HR=0 → 属性设置成功但 WPF 合成目标不透明，材质被遮挡。基线结论：**透射 0，非 7.84%**。

## 一、做了什么

1. **`CompositionTarget.BackgroundColor = Colors.Transparent`**（`WindowBackdropController.OnSourceInitialized`）：修复 WPF `HwndTarget` 不透明合成（头号真因）。
2. **返回值检查 + 回读**（`DwmHelper` 重写）：`DwmExtendFrameIntoClientArea` 必须返回 0；`DwmSetWindowAttribute` 记录 HRESULT；`DwmGetWindowAttribute` 回读 corner/dark/backdrop 属性（不再"设了不验"）。
3. **分帧激活**：先设 `backdrop=NONE(1)`，250ms 后的独立 DispatcherTimer 合成帧再设 `Acrylic(3)`；每次重绑都会重新走该序列。
4. **重做帧扩展的时机补齐**：`SourceInitialized` / `ContentRendered` / `IsVisibleChanged(visible)` / `WM_DWMCOMPOSITIONCHANGED` / `WM_THEMECHANGED` / `WM_SETTINGCHANGE`，**每次显示都重做**（§7.3）；`IsVisibleChanged(false)` 取消分帧定时器。
5. **降级路径**：DWM 合成关闭 / `EnableTransparency=0` / 高对比度 / `AllowsTransparency=true` / Build<22621 / `CompositionTarget` 不透明 → 记录原因并切换到**明确静态底**（同 RGB 不透明 `#14161C`），材质未就绪前表面也保持不透明，避免灰板。
6. **首帧埋点（`FirstFrameTimer`）**：`Program.Main` 首行 `Arm()`；`MainWindow` 订阅首个 `CompositionTarget.Rendering` 并 `NotifyFirstFrame()`；记录 elapsedMs / build / round / osBuild / session / pid；`PERF-01` 明确改为 **uptime（非首帧）**，新增 `PERF-02` 验证埋点通路（自检无窗口不产生数值）。
7. **`SYS-02`**：判据改为 `osMajor>=10 && build>=22000`，区分 Win10/Win11。
8. **`FS-01`**：描述已在 PR-S0-04 对齐为「数据目录写入/读取/删除闭环测试（原子覆盖由 FS-02 验证）」；本 PR 未再改实现（理由：原子替换由 FS-02 真正覆盖，FS-01 不应冒充原子）。
9. **诊断入口**：`--diagnose-window`（HRESULT/回读/分帧时序/隐藏-显示重做）、`--diagnose-window-fallback`（强制降级）、`--diagnose-first-frame`（真实首帧测量）。
10. **α 数值未改**：根 surface 仍 α235；材质就绪时才切回 α235 表面，降级时只把同一 RGB 换为不透明。

## 六、解锁后复测（2026-11-08，Session 1 已解锁；抓屏纯色对照先行）

### 6.1 Acrylic 透射率（背板 0→255 阶梯，纯色控制）
- **抓屏对照**：先放全屏品红背板，`captureControlPixel=255,0,255`（像素精确）→ 抓屏管线可信。
- **Acrylic(3) 实测**：controlOk=true；内部 luma 24（backdrop=0）→31（backdrop=255）；**slope=0.02939、R²=0.9887**。
- **NONE(1) 对照**（同一窗口把 backdrop 设为 NONE 后重跑 0/128/255）：内部 luma 20→30→40；**slope=0.07843、R²=1.0000**，与 α235 理论值 0.0784 完全一致。
- 结论：**合成遮挡已解除**——NONE 对照证明帧扩展 + `CompositionTarget` 透明生效（原始背板透射 7.84%）；Acrylic(3) 下仍有透射（0.0294，约为原始值的 37.5%），衰减来自 Acrylic 自身 tint，不是遮挡。
- 按 Lead 的严格判据（Acrylic slope≈0.0784、R²>0.95）：**未达标**（0.0294 不落在 0.0784±容差内），因此 `S0-WIN-03` **保持未验证**，等待所有者/Lead 决定是否将 tint 因子纳入判据。修复前基线为内部 luma 恒 20.01（斜率 -0.0001/R²=0.0004）。

### 6.2 降级静态底像素（真实 `EnableTransparency=1→0`，随后恢复=1）
- controlOk=true（品红精确）；背板 0→255 九档内部 luma **恒 22**，slope=0/R²=0；表面为不透明静态色，未出现 165 灰板。
- 结论：降级分支"明确静态底色、不崩、不变灰板"有像素证据；`S0-WIN-04` 可判通过。

### 6.3 首帧（`--diagnose-first-frame`，解锁桌面）
- 起止定义：`Program.Main` 首行 Arm → 首个 `CompositionTarget.Rendering` 回调；`elapsedMs=368.10`、`build=Debug`、`round=1`、`osBuild=26220`、`session=1`；< 800ms。
- 与 `PERF-01`（uptime）分开记录，不混用。

### 6.4 关窗行为复核（QA 报"托盘可用却退出"）
- 代码分支本身正确（`MinimizeToTrayOnClose && TrayService!=null && IsTrayAvailable` → Cancel+Hide；否则 Shutdown）。用内部诊断直接调用真实 `ApplyCloseBehavior`（不经 `WM_CLOSE`/`CloseMainWindow`），日志同时打出：`minimizeToTrayOnClose=true`、`trayServiceNull=false`、`trayAvailable=true` → `expectedHide=true`、`cancel=true`、`visibleAfter=false`、`shutdownStarted=false`，进程存活；`no-tray` 场景三值中 trayAvailable=false → `expectedHide=false`、`cancel=false`，产品逻辑调用 Shutdown，进程退出。两场景 exit=0、同一 PID/窗口数/时间戳留证。
- **发现并修复的真实缺口**：`AppSettings.MinimizeToTrayOnClose` 从未绑定到 `MainWindow`（App 未加载 SettingsStore，属性只在构造器硬编码 true）。已在 `App.OnStartup` 加载 `SettingsStore` 并应用该值；诊断同步走真实绑定（settings 文件缺省 → true）。
- 结论：**不是 PR #7 "修过头"**；若托盘真的可用，现有代码不会退出。QA 观测到的退出更可能发生在"该进程内 tray 实际不可用"或测试口径（如第二实例接管）下；`App.cs` 未设置 `ShutdownMode`（默认 `OnLastWindowClose`），隐藏窗口不触发退出，这与"退出只可能来自 else 分支"的推理一致。事件计数类断言已绑定 PID/窗口数/时间戳，避免另一实例贡献。

## 七、判据裁决落实（2026-11-08，Lead 裁决后）

- **`S0-WIN-03` 修订判据**（写入矩阵）：① 纯色抓屏对照像素精确；② `NONE(1)` 对照 slope 达 α235 理论值（证明合成遮挡解除）；③ `Acrylic(3)` slope>0 且 R²>0.95（证明材质真实透射且线性相关）。**不要求** Acrylic slope 等于无 tint 理论值——原 0.0784 判据假设"透射=1-α"，忽略了 Acrylic 自身 tint 的二次衰减。
- 实测：品红对照 `255,0,255` 精确；`NONE` 20→30→40、slope **0.07843**/R² **1.0000**；`Acrylic` 24→31、slope **0.02939**/R² **0.9887**。三条全满足 → `S0-WIN-03` **通过**。**必须保留的说明**：`0.0294` 是 tint 衰减后的值，不是缺陷；原始 7.84% 透射由 `NONE` 对照证明。α235 的 37.5% 衰减是所有者决定"是否降 α"的依据，本 PR 未调 tint/α。
- **`S0-WIN-04` 补注**：降级态是**明确的静态底色**（同 RGB 不透明 `#14161C`，九档内部 luma 恒 22、slope=0），不是材质残留；真实 `EnableTransparency=1→0` 后恢复并回读=1。
- **`S0-FIRSTFRAME-01` 补注**：368.10ms（Debug/round1/osBuild26220/session1，起止=`Main` 首行→首个 `CompositionTarget.Rendering`）；`PERF-01` 仍报 uptime，两者**分列不混**。
- **单列真缺口（价值高于本次修复）**：修复前 `AppSettings.MinimizeToTrayOnClose` 是**死值**——`MainWindow` 仅在构造函数硬编码 `true`，`App` 从未加载 `SettingsStore`，用户在设置页修改关闭行为不会生效（S0 的"设置存储"与"外壳行为"未接通）。PR-S0-05 在 `App.OnStartup` 加载 `SettingsStore` 并应用该值，诊断同步走真实绑定；修复前/后行为差异与证据见 §6.4。

## 八、WIN-03 样本量打回与 9 档复测（2026-11-08）

- **首轮数据被驳回（留痕）**：我最初报的 `NONE` 只有 **3 点**、`Acrylic` 只强调了 **2 个端点**；`R²=1.0000` 在 3 个点上没有统计意义。QA 独立复跑时踩到同一类陷阱（背板未逐档重绘，9 档里只有 2 个不同值），它自查后判为假绿、不采信。**样本不足，不得判材质呈现。**
- **重测仪器要求**：背板 0→255 **9 档**（0/32/64/96/128/160/192/224/255）；每档断言 `backdropObserved` 真的变化；打印全部 9 个 `(backdrop, interiorLuma)`；断言 x 轴 **≥5 个不同值**；`NONE` 与 `Acrylic` 在同一窗口连续各跑一遍，绑定同一 PID/窗口句柄/时间戳区间；同轮先跑纯色对照。
- **QA 独立复验结果（修好仪器后）**：`NONE(1)` observed 与 target 逐档相等，interior 20.008→40.008，**slope=0.07829 / R²=0.99860 / 9 个不同 x**（与 α235 理论 0.0784 差 0.0001）；`Acrylic(3)` 9 档对齐，**slope=0.02924 / R²=0.98891 / 9 个不同 x**（末两点均为 31.008 是 8bit 量化饱和，不影响 R²）。三条修订判据全满足 → **`S0-WIN-03` 判通过**；矩阵证据列已标注「独立复验方测量，非实现方自证」。
- **保留的两句判据说明**：`0.0294` 是 Acrylic tint 衰减后的值，不是缺陷；原始 7.84% 透射由 `NONE` 对照证明。α235 的 37.5% 衰减是所有者决定「是否降 α」的依据，本 PR 未调 tint/α。
